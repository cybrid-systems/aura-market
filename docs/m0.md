# M0 smoke sequence

Deterministic Soft script `soft/market/m0_smoke.aura`. Seed `20261005`,
48 ticks. Dialect string: `live-orderbook-market-m0`.

One book. One taker per tick. Two market makers. The numbers are the race.

## Law

1. Seed step: `(modulo (+ (* seed 75) 74) 65537)`. The first word is
   `34567`. Each tick uses one word, then steps.
2. From word `r`: taker side `r mod 2` (0 buys / lifts the ask, 1 sells /
   hits the bid), qty `1 + (r/2 mod 4)`, aggression `r/8 mod 4`, fair
   drift `(r/32 mod 3) - 1`. Fair starts at `100`.
3. Each tick: fair drifts, the MM computes `(bid-px bid-qty ask-px ask-qty)`
   from `(fair inv)`, both quotes pass the gate, accepted quotes form the
   book (cancel/replace every tick).
4. Gate, in order: `qty < 0` → `negative-qty`; `qty = 0` → `zero-qty`;
   `px <= 0` → `non-positive-px`; a bid at or above the same MM's live ask
   → `crossed-self-trade`; `inv + bid-qty > 10` or `inv - ask-qty < -10`
   → `over-inventory-limit`. A rejected quote never rests.
5. The taker is IOC. A buy fills against the ask when
   `ask-px <= fair + aggression`; a sell fills against the bid when
   `bid-px >= fair - aggression`. Fill size is `min(taker, resting)`. The
   remainder of the resting order stays in the book for that tick.
6. MM inventory moves opposite the taker. Cash moves by `fill * px`.
7. `pnl = cash + inv * fair_end`.
   `penalty = quotient(sum over ticks of |inv|, 4) + 2 * |inv_end|`.
   Score is `pnl - penalty`.

## Strategies

| mid | name | bid | ask | sizes |
|-----|------|-----|-----|-------|
| 1 | `mm-tight` | `fair - 1 - qdiv(inv, 2)` | `fair + 1 - qdiv(inv, 2)` | bid `3 - 2·inv`, ask `3 + 2·inv` |
| 2 | `mm-wide` | `fair - 3` | `fair + 3` | 5 / 5 |

`mm-tight` shrinks the side that would grow its inventory, but it does not
clamp at zero. One fill of 2 drives a size negative. The gate rejects it
(`negative-qty`) and the book is one-sided until inventory comes back.
`mm-wide` quotes 5 into an inventory limit of 10. Past `|inv| > 5` the gate
rejects the side that would breach (`over-inventory-limit`).

Neither strategy calls `set-code`. M0 does not `hot-strategy:register!`
them.

## Race

Same seed, both strategies. The race thunks only return a score. They do
not `set!` the main book, so a real fiber cannot publish the loser's
inventory into the live world.

`fiber:spawn` both thunks, then `fiber:join`. `fiber_live` only when the
ids are distinct and positive, both joins are numbers, `joins` equals
`spawned`, and `fiber:spawn-backend` is `> 0`. Otherwise the thunks run on
the host and the stamp is `host-sequential`.

After the race a pure host audit pass replays both strategies with the
gate log on. It prints the first three `REJECT` lines per strategy and the
`REJECTS` totals. It writes no world slot.

The strictly higher score wins (`higher-score-stamp` /
`lower-score-rollback`). A tie would KEEP tight (`tie-keep-tight-stamp`).
This seed is not a tie.

The winner is replayed with the tape on and stamped into the main book.
The loser is not stamped. That is the rollback.
